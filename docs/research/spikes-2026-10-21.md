### Design consequences (to fold into the spec after live checks)

1. **Per-agent MCP identity (S1):** do not copy Paseo's shared token. In `before agent.create`, mint a random per-agent token, put it in the injected MCP server's `headers` and in `env.SLP_TOKEN`; in `agent.session_open` (has `agentId` + env) bind token → agentId + role. Role comes from the provider ID at create time.
2. **Limit watchdog (S2):** detect from the turn's last assistant text and failed-turn message (official recipe style), and take reset times from `providers.listUsage()` instead of parsing text. Keep backoff as fallback.
3. **Human-message detection (S4):** human = `user_message` with no `<paseo-system>` envelope and a `messageId` the plugin did not issue. Residual: an agent calling `paseo send` via shell is indistinguishable from the human → S3 matters.
4. **Permission engine (S5):** run SLP Claude roles in `default` mode (+ `toolPolicy` preapprovals for safe tools) so Bash reaches the plugin; avoid `auto`/`bypassPermissions` for SLP roles.
5. **Rotation threshold (S7):** use `contextWindowUsedTokens / contextWindowMaxTokens`; drop the turn/compaction fallback unless a provider omits it.
6. **Spawn (S8):** `slp_spawn` passes `parent` → native Subagents nesting and parent notifications come back; router still handles non-parent routing.
7. **Codex Peer-impl (S9):** set `sandbox_workspace_write.writable_roots` to the repo's git common dir; keep `network_access: false`.
8. **Router (Extra):** the plugin must queue itself and deliver only when the target is `idle` (or deliberately `steer`); never rely on the daemon default, which interrupts.

### Delta to the running version (0.12.0)

The Paseo app auto-updated to **0.12.0** during the day (CLI and daemon both report 0.12.0; tag `v0.12.0`, commit `cafe4b0`). Re-checked in 0.12.0 source: `callerAgentId` URL pattern (`runtime-mcp-config.ts:50`), Codex `sandbox_workspace_write.writable_roots/network_access` (`codex/options.ts:41-45`), `contextWindowUsedTokens` (`messages.ts:392`), SDK `agents.create({parent})` (`client/index.ts:249`), plugin lifecycle event names (`plugin/src/server/lifecycle.ts:48-63`), still no usage/rate-limit detection in the Claude provider. Round-1 verdicts hold.

Changes that matter (CHANGELOG 0.11.0 → 0.12.0):
- **Agent-to-agent messages are attributed** (#6373). `paseo send` reads `PASEO_AGENT_ID` and sends `sourceAgentId` (`packages/cli/src/commands/agent/send.ts:202-207`); the daemon wraps the prompt in a versioned `<paseo-system version="1" … message-id=…>` envelope with `source-agent-id`, and the timeline projects it as a `tool_call` named `agent_message` with `sender {id, title}` instead of a `user_message` (`packages/server/src/server/agent/agent-messages/index.ts:112-176`, `session.ts:8206-8232`). → Human prompts stay `user_message`; agent prompts sent through the CLI/MCP become `agent_message`. **Spoofable:** an agent that runs `env -u PASEO_AGENT_ID paseo send …` looks human again.
- **CLI/MCP agent sends now steer** the running turn instead of interrupting (#5164); human CLI sends still default to `interrupt`. Router rule unchanged: plugin delivers when the target is `idle`.
- `paseo usage` CLI and plugin "usage sources" expose quota windows and reset times (#6474, #5465).
- `agent.closed` lifecycle event added (0.11.0, #5971); parent finish-notification races fixed (#6008, #6660).

## Verdicts

| Spike | Verdict | Design change |
|---|---|---|
| S1 | ✅ | Per-agent token via `before agent.create` + `session_open`; plugin auto-approves permission requests for its own `slp_*` tools |
| S2 | ◐ | Reset times from `providers.listUsage()`; limit detection by text on the turn's last assistant message / failed-turn message; first real limit hit must be logged and the matcher adjusted |
| S3 | ◐ | Codex sandbox blocks the `paseo` CLI and writes outside the worktree, but **loopback to the daemon is open**. Residual risk: a determined Codex agent could talk to the daemon's WebSocket directly. Mitigation candidates: daemon password, plugin audit of `agent_message` senders |
| S4 | ✅ | Human = `user_message` without a plugin-issued `messageId` and without a `<paseo-system>` envelope |
| S5 | ✅ | SLP Claude roles run in `default` mode; plugin is the permission engine (read-only commands are auto-allowed by Claude Code itself) |
| S6 | ✅ | Superpowers stays the code-level evidence core inside Claude roles |
| S7 | ✅ | Rotation threshold = `contextWindowUsedTokens / contextWindowMaxTokens` |
| S8 | ✅ | `slp_spawn` passes `parent`; native Subagents nesting and parent notifications preserved |
| S9 | ❌ | Codex Peer-impl in `workspace-write` cannot commit. Proposed: **plugin commits on the Peer's behalf at `slp_report`** (it then knows the exact commit to verify). Alternative: plugin auto-approves only exact `git add`/`git commit` escalations |
