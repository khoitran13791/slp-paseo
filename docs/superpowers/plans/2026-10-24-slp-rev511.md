# SLP rev 5.11 (no per-project setup) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** After a one-time install, SLP works on any repo: the plugin registers the repo when a Supervisor starts in it, each feature finds its own base branch, and the full-suite verify command comes from the approved spec instead of `~/.slp/config.json`.

**Architecture:** A new `ProjectRegistry` (`plugin/server/projects.ts`, file `~/.slp/projects.json`) replaces `config.projects`; `transformCreate` registers the repo for a new Supervisor. `resolveBaseBranch` (git.ts) runs at the first Lead spawn, and the result goes into the Lead's `assign` event, which `deriveFeature` exposes as `baseBranch`. `slp_spec` takes `verify: string[]` and checks it against a `## Verify` section; `deriveFeature` exposes the latest approved spec's commands as `approvedVerify`, and `slp_ship_package` runs those.

**Tech Stack:** TypeScript (Node 22), zod 4, vitest 3, git CLI, Paseo plugin SDK 0.12.

**Spec:** `docs/superpowers/specs/2026-10-21-slp-paseo-design.md` rev 5.11 (commit a559c1d): §5.2, §5.3, §6.2, §6.7, §7 (shared rules), §7.4, §8, §9, §11.

**Core mechanism:**
- **New repo:** the human creates a Supervisor in the repo → `ProjectRegistry.register(cwd, remote)` runs its checks → the result goes into `~/.slp/projects.json`.
- **New feature:** the first Lead spawn runs `resolveBaseBranch`, which fetches and picks a branch → `assign.baseBranch`.
- **Ship:** the Lead's `slp_spec` records `verify` → the human approves the spec → `approvedVerify` → `slp_ship_package` runs it in the sandbox.

**Decisions:**
- The repo is found by walking up for `.git` (file system only), since running git in a directory that is not trusted yet could run its config.
- The base branch belongs to the feature, recorded once, so a remote that changes its default branch mid-feature cannot move the feature.
- `verify` lives in the spec, so the human approves the command along with the spec.
- A feature from before rev 5.11 has no recorded base: it is resolved on demand.

**System impact:**
- The human no longer edits `~/.slp/config.json`, which becomes optional; a leftover `projects` section is ignored with a log line.
- A Supervisor started outside a git main checkout, in a repo with command-running git drivers, or without the `ship.remote` remote fails to start, with a message saying how to fix it.
- `slp_spec` without `verify` or `## Verify` is refused.
- Every feature starts from a freshly fetched remote branch.
- The PR base drops the remote name, whatever it is.
- `limits.maxWriters` replaces `projects.<name>.maxWriters`.

**Task groups:**
- T1 Verify in the spec. The ship gate needs a command once `config.projects` goes away; it must land before T5 removes it.
- T2 Prompts. The Lead must find and baseline the command, and the Supervisor must show it to the human. Needs T1's tool shape.
- T3 Base branch per feature. Every git step that used `project.baseBranch` needs the feature's base before T5 removes the setting.
- T4 Project registry module. Standalone, so its checks can be tested before anything depends on them.
- T5 Switch to the registry. Removes `config.projects` and needs T1, T3 and T4.
- T6 README, example config and the live smoke. Checks the whole flow on a repo SLP has never seen.

## Global Constraints

- The plugin finds the repo root by walking up from the agent's folder to the first `.git`, "chỉ bằng đọc file: không chạy git trong một thư mục chưa tin" (§7.4).
- `.git` must be a directory with `HEAD`. If it is a file (a worktree or submodule), refuse with "open the repo's main checkout" (§7.4).
- A repo with command-running git drivers is refused, naming the driver (§7.4 step 3, existing `unsafeGitDrivers`).
- The remote `ship.remote` must exist, else refuse with "push the repo to a remote first" (§7.4 step 4).
- Project name: the root folder's name as a slug ("chữ thường, ký tự khác `a-z0-9` thành `-`"). On a clash with another repo's name, append `-` and the first 4 hex characters of the sha256 of the realpath. A repo registered before keeps its name (§7.4 step 5).
- `~/.slp/projects.json` has the shape `{ "<name>": { "repo": "<realpath>" } }`. At start the plugin trusts every repo in it again; a repo that is gone is logged and skipped. A `projects` section in `config.json` is ignored with one log line (§7.4 step 6, §8).
- Base branch: fetch the remote first, then try in order `<remote>/HEAD` → the upstream of the branch checked out in the main checkout → `<remote>/main` → `<remote>/master`. If none exists, `slp_spawn` fails. The result is stored in the Lead's `assign` as `baseBranch`. There is no way to configure another base branch (§7.4).
- `slp_spec` takes a required `verify: string[]` and refuses a spec with no `## Verify` section, or one where any command in `verify` does not appear verbatim in that section (§6.2).
- Ship runs the `verify` of the latest approved spec on the HEAD of `feat/<slug>`, in the sandbox (§5.3, §6.7).
- `~/.slp/config.json` is optional; without the file, every value takes its default. `limits.maxWriters` defaults to 2 (§8).
- Per-task `verify` in the plan stays as it is (§6.2).
- Code, prompts, tool text and commit messages are in English (rev 5.10 language rule).
- Commands: `cd plugin && npx vitest run <file>` for one file, `npx vitest run` for the suite, and `npm run typecheck`. The suite was green before this plan: 443 passed, 1 skipped.

## Review Focus

1. A remote whose `origin/HEAD` still points to a deleted branch should be skipped, falling back to the next candidate instead of failing (T3 test "skips an origin/HEAD whose branch is gone").
2. With `ship.remote` not named `origin`, fetch, base and PR base should all use that name (T3 test "strips the remote name from the PR base").
3. A feature that started before rev 5.11 has no `baseBranch`. `slp_merge_main` and ship should resolve one instead of crashing (T3 test "falls back to resolving the base for a feature from before rev 5.11").
4. A verify command inside a fenced code block in `## Verify` passes, and a command that appears only in another section fails (T1 test).
5. A repo reached through a symlink, or with a name that has spaces or capitals, should get the same project name every time (T4 tests "symlink" and "My App").

/** The spec's "## Verify" section must name every full-suite command slp_spec records (spec §6.2 rev 5.11). */
function verifySectionProblem(markdown: string, verify: readonly string[]): string | null {
  const head = /^##\s+Verify\b.*$/m.exec(markdown);
  if (!head) return 'the spec needs a "## Verify" section: the command(s) that run the whole test suite, and the result of running them once before the spec (rev 5.11)';
  const rest = markdown.slice(head.index + head[0].length);
  const next = /^##\s/m.exec(rest); // "### sub" headings stay inside the section
  const section = next ? rest.slice(0, next.index) : rest;
  const absent = verify.filter((c) => !section.includes(c));
  return absent.length ? `these verify commands are not in the "## Verify" section: ${absent.join("; ")}` : null;
}
```

/**
 * A feature's base branch (spec §7.4 rev 5.11): fetch, then <remote>/HEAD, the upstream of the branch checked out in the main
 * checkout, <remote>/main, <remote>/master. Network git runs in the human's checkout, like pushNoHooks.
 */
export function resolveBaseBranch(repo: string, remote: string): string {
  git(repo, ["fetch", "--quiet", remote], true);
  const exists = (ref: string) => git(repo, ["rev-parse", "--verify", "--quiet", `refs/remotes/${ref}`], true).code === 0;
  const head = git(repo, ["symbolic-ref", "--quiet", "--short", `refs/remotes/${remote}/HEAD`], true).stdout.trim();
  if (head && exists(head)) return head; // a HEAD left pointing at a deleted branch is skipped
  const upstream = git(repo, ["rev-parse", "--abbrev-ref", "--symbolic-full-name", "@{upstream}"], true).stdout.trim();
  if (upstream.startsWith(`${remote}/`) && exists(upstream)) return upstream;
  for (const b of ["main", "master"]) if (exists(`${remote}/${b}`)) return `${remote}/${b}`;
  throw new Error(`no base branch on ${remote}: tried ${remote}/HEAD, the upstream of the current branch, ${remote}/main and ${remote}/master; push the default branch to ${remote}`);
}

export interface ProjectEntry { repo: string }
export class ProjectError extends Error {}

/** Walks up from `cwd` to the first folder holding `.git`, reading the file system only: no git runs in a folder SLP does not trust yet. */
export function findRepoRoot(cwd: string): { root: string; dotGit: "dir" | "file" } | null {
  let dir = realpathSync(cwd);
  for (;;) {
    const p = join(dir, ".git");
    if (existsSync(p)) return { root: dir, dotGit: statSync(p).isDirectory() ? "dir" : "file" };
    const up = dirname(dir);
    if (up === dir) return null;
    dir = up;
  }
}

export const projectSlug = (dir: string): string => basename(dir).toLowerCase().replace(/[^a-z0-9]+/g, "-").replace(/^-+|-+$/g, "") || "repo";

/** `~/.slp/projects.json`: the repos SLP registered when a Supervisor started in them. Only the plugin writes it. */
export class ProjectRegistry {
  private entries: Record<string, ProjectEntry> = {};
  private corrupt = false;
  constructor(private readonly file: string, private readonly log: (message: string, error?: unknown) => void = () => undefined) {
    if (!existsSync(file)) return;
    try { this.entries = JSON.parse(readFileSync(file, "utf8")) as Record<string, ProjectEntry>; } catch (error) { this.corrupt = true; this.log(`${file}: projects.json is not valid JSON; starting with no projects, the file is kept as projects.json.bad on the next write`, error); }
  }

  /** After a restart: trust every registered repo again. A repo that is gone or now runs git drivers is logged and left untrusted. */
  trustAll(): void {
    for (const [name, p] of Object.entries(this.entries)) {
      try {
        trustRepo(p.repo);
        const drivers = unsafeGitDrivers(p.repo);
        if (drivers.length) this.log(`project ${name}: git config runs commands a Peer could change (${drivers.join("; ")}); SLP will refuse to start agents here until they are removed.`);
      } catch (error) { this.log(`project ${name}: ${String(error)}; skipped`); }
    }
  }

  names(): string[] { return Object.keys(this.entries); }
  get(name: string): ProjectEntry | null { return this.entries[name] ?? null; }

  /** The project of a Supervisor started in `cwd`, registered on first use. Throws ProjectError saying how to fix the repo. */
  register(cwd: string, remote: string): { name: string; repo: string } {
    const found = findRepoRoot(cwd);
    if (!found) throw new ProjectError(`SLP: ${cwd} is not inside a git repo. Open a git repo's folder in Paseo and start the Supervisor there.`);
    if (found.dotGit === "file") throw new ProjectError(`SLP: ${found.root} is a git worktree or submodule. Open the repo's main checkout in Paseo and start the Supervisor there.`);
    const repo = found.root;
    trustRepo(repo); // throws when .git has no HEAD
    const drivers = unsafeGitDrivers(repo);
    if (drivers.length) throw new ProjectError(`SLP: ${repo}'s git config runs commands a Peer could change (${drivers.join("; ")}). Remove them, or keep this repo out of SLP.`);
    if (git(repo, ["remote", "get-url", remote], true).code !== 0) throw new ProjectError(`SLP: ${repo} has no remote "${remote}". Push the repo to a remote first: features start from it and ship pushes to it.`);
    const known = Object.entries(this.entries).find(([, p]) => p.repo === repo);
    if (known) return { name: known[0], repo };
    let name = projectSlug(repo);
    if (this.entries[name]) name = `${name}-${createHash("sha256").update(repo).digest("hex").slice(0, 4)}`;
    this.entries[name] = { repo };
    mkdirSync(dirname(this.file), { recursive: true });
    if (this.corrupt) { copyFileSync(this.file, `${this.file}.bad`); this.corrupt = false; }
    writeFileSync(this.file, `${JSON.stringify(this.entries, null, 2)}\n`, { mode: 0o600 });
    return { name, repo };
  }
}
```
