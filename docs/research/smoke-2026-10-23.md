## Bugs found
- **B-1 (roles/runtime): role setup is a one-time snapshot.** `runtime.ts` `capture()` reads `paseo.config.get()` once, on the first hook after plugin load (03:11), and caches `setup`. The agent profiles were created later (~03:40), so `setup.profile.lead` was empty, `providerString("lead", undefined)` returned bare `slp-lead`, and the client threw the cryptic `provider/model` error. Fix (TDD, owning task of `runtime.ts`/`roles.ts`): re-read config when creating an agent (or on config change), and fail with a clear message when a role has no profile and no model (`SLP: no agent profile for provider slp-lead; create one in Settings → Agent profiles`).
- **B-2 (tools/work.ts, minor):** `slp_spawn` accepts `model` for `role: "lead"` but ignores it (`createAgent(... "lead" ...)` passes no `model`). Either honor it (subject to `models.allowed`) or reject it for the Lead.
- **B-3 (security, authority): Supervisor and Lead see Paseo tools that step outside SLP.** `disabledTools` removes only `create_agent`, `send_agent_prompt`, `kill_agent`. Still listed: `create_terminal`/`send_terminal_keys` (shell run by the daemon, outside the Claude sandbox), `*_schedule`/`create_heartbeat` (start non-SLP agents), `set_agent_mode`/`update_agent` (a switch to `bypassPermissions` silences the plugin's permission policy; `--allow-dangerously-skip-permissions` is on the command line), `respond_to_permission`, `*_workspace`, `start_workspace_script`, `browser_*`. **Probe 04:0x: the gate does not hold.** Asked the Supervisor to call `list_terminals` once: it ran with no permission prompt and returned `{"terminals":[]}` (no permission request reached the plugin or `paseo permit ls`). So `create_terminal`/`send_terminal_keys` would run an unsandboxed shell with no human in the loop. Containment at 04:1x: `slp-supervisor` and `slp-lead` set to `paseoTools: {enabled: false}` (backup `config.json.bak-slp-b3`), `paseo reload` → `appliedPaths: [agents.providers]`. The SLP prompts use no Paseo tool (`slp_activity`/`slp_state` cover reads). Probe 2 after the reload: the already-running Supervisor still called `list_terminals` (`{"terminals":[]}`), so provider config binds at process launch. `paseo agent reload <id>` on the Supervisor (idle) and then the Lead (idle) restarted their processes with session kept (`timelineSize` 73 / 40). New Supervisor process: `--mcp-config` has only `slp` (no `127.0.0.1:6767/mcp`), sandbox, `--setting-sources` (empty), `--strict-mcp-config`, `--plugin-dir` all kept, so the plugin's create-time transform survives `agent reload`. ## Decisions after the run (human, 2026-10-23)
- **Brainstorm is the most thorough step, done with the human, and it ends in the spec.** The Supervisor brainstorms with the human (superpowers:brainstorming style: one question at a time, purpose first, 2–3 approaches with trade-offs, edge-case sweep, write-back of "you said" vs "I assume").
- **The Supervisor may call the Lead into the brainstorm for hard questions** (several viable approaches with different consequences, answers that need reading or probing the repo, hard-to-reverse choices); easy or preference questions stay between the Supervisor and the human. The Lead joins in a consult mode: reads the repo, runs sandboxed probes, proposes and challenges with evidence; no Peers yet.
- **Supervisor and Lead debate each other and the human** to reach the best spec: the Supervisor speaks for the human's stated intent (quotes), the Lead for feasibility (repo evidence, probes); options go to the human as a comparison table; the human may message the Lead directly (the Supervisor is told).
- **Brief gate removed.** The brief is only the brainstorm's working record. Blocking human gates: spec (end of the brainstorm) and ship. Plan stays Supervisor-approved, written by the Lead with superpowers:writing-plans.
- Supersedes the earlier idea of a non-blocking spec note.
- Needs: spec revision (flow §, gates, roles), plugin change so `slp_spawn lead` is allowed before any approval in consult mode while Peer spawns stay locked until spec + plan approval, prompt rewrites for Supervisor and Lead.
